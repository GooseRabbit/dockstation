# DockStation Operator — первая Windows-версия

**Статус:** QML-прототип GUI этапа 3 мастер-плана. Базовый интерфейс ранее
проверялся владельцем на Windows; текущие изменения списка локальных профилей
требуют повторной ручной проверки. Целевая Repka Pi 5 ещё не проверялась.

Это графический клиент для первого VM-этапа DockStation: пользовательская часть остаётся read-only; отдельно предусмотрен программный test-only PING для проверки сквозного взаимодействия без управления оборудованием. Он создаёт
локальный SSH-туннель к Linux VM, опрашивает опубликованный Gateway API и
показывает системную и сетевую диагностику. Обновление выполняется автоматически
каждые пять секунд; устаревшие данные остаются видимыми, но явно помечаются.

**Текущий охват:** операционная система, версия ОС, ядро, архитектура, uptime,
RAM, корневая файловая система, температура CPU/SoC при наличии явно
маркированной thermal zone, load average, сетевые интерфейсы и адреса, маршруты
по умолчанию, DNS и состояние SSH-службы. Системные ресурсы передаются в
`platform.resources`; каждый показатель имеет независимый статус, а недоступные
числовые значения остаются `null`. Load average не является процентом загрузки CPU.
Приложение не подменяет отсутствующие показатели нулём или вымышленными значениями.

## Требования для Windows

- Windows 10 или 11.
- Python 3.11 или новее.
- PySide6 6.8 или новее (устанавливается вместе с QML-вариантом приложения).
- Компонент Windows **OpenSSH Client**: `ssh.exe` и `ssh-keygen.exe`.
- Доступ Windows-хоста к Linux VM по адресу host-only сети или настроенному
  перенаправлению SSH-порта виртуальной машины.
- Приватный SSH-ключ и отдельный файл `known_hosts` с предварительно проверенным
  host key Linux VM.

Проверить наличие OpenSSH можно в PowerShell:

```powershell
ssh -V
ssh-keygen -?
```

## Подготовка доверенного host key

Не используй результат `ssh-keyscan` как доказательство подлинности сервера:
он только получает ключ, но не удостоверяет, кому этот ключ принадлежит.

1. На самой Linux VM получи SHA-256 отпечаток публичного host key. Для Ed25519:

   ```sh
   sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256
   ```

2. На Windows получи ключ именно от того IP/имени и SSH-порта, которые затем
   будут указаны в приложении. Например, для порта 22:

   ```powershell
   ssh-keyscan -t ed25519 -p 22 192.0.2.10 | Out-File -Encoding ascii .\dockstation_known_hosts
   ssh-keygen -lf .\dockstation_known_hosts -E sha256
   ```

3. Сравни отпечаток Windows с отпечатком, полученным непосредственно на Linux VM,
   по независимому доверенному каналу. Только при полном совпадении используй
   созданный `dockstation_known_hosts`. Если Ed25519 host key на VM отсутствует,
   используй фактически настроенный тип ключа и соответствующий `-t` в
   `ssh-keyscan`.

При изменении host key приложение намеренно откажет в подключении, пока новый
отпечаток не будет проверен и корректно добавлен в файл `known_hosts`.

## Установка и запуск

Открой PowerShell в каталоге `operator`:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[qml]"
dockstation-operator-qml
```

`dockstation-operator` устанавливается как Windows GUI entry point и открывает
окно без отдельного консольного окна.

В приложении укажи:

- адрес Linux VM;
- имя Linux-пользователя;
- SSH-порт (обычно 22);
- путь к приватному SSH-ключу;
- путь к подготовленному `known_hosts`.

Локальный порт Windows по умолчанию — `18080`; внутри Linux VM Gateway должен
слушать `127.0.0.1:8080`. Если порт 18080 уже занят, выбери другой свободный
локальный порт в приложении. Удалённый порт API в текущем срезе фиксирован на
8080 и не открывается в локальную сеть.

Профиль хранит только адрес, имя пользователя, номера портов и пути к файлам.
Содержимое приватного ключа и пароль в настройки приложения не копируются.
Для ключа с парольной фразой заранее загрузи его в Windows OpenSSH Agent;
приложение работает в неинтерактивном режиме и не запрашивает пароль.

## Несколько локальных профилей подключения

В QML-интерфейсе можно создать несколько лабораторных SSH-профилей, задать
каждому локальное имя и переключаться между ними в боковом списке. Для нового
профиля нажми «+ Добавить профиль», заполни имя, адрес Linux VM, пользователя,
порты, SSH-ключ и known_hosts, затем сохрани профиль.

Реестр хранится отдельно от прежнего одиночного профиля:

- Windows: `%LOCALAPPDATA%\DockStationOperator\stations.json` (либо
  `%APPDATA%\DockStationOperator\stations.json`, если LOCALAPPDATA не задан);
- другие ОС: `~/.config/DockStationOperator/stations.json`.

Это **локальные профили данного компьютера и пользователя Windows**, а не
каталог станций учётной записи DockStation. Локальный `profile_id` не является
Station ID. Имена пока не синхронизируются с сервером или другими устройствами.
В этой промежуточной версии активен один SSH/API-сеанс; профиль, который ещё
не проверялся, отображается как «Неизвестно». Независимый фоновый опрос всех
станций и серверная авторизация пока не реализованы.

## Что реализовано

- Проверка профиля и параметров подключения.
- Проверка наличия записи для указанного узла в выбранном `known_hosts` через
  `ssh-keygen`.
- SSH local-forward только между `127.0.0.1` Windows и `127.0.0.1` Linux VM.
- Строгая проверка host key; неизвестный или изменённый ключ не принимается.
- HTTP GET к `/api/v1/health` и `/api/v1/system/diagnostics`.
- Отдельный метод `submit_test_adapter_request()` отправляет только безопасный `PING` по `POST /api/v1/test/adapter/request`; это проверочная возможность без физического исполнения. Маршрут должен быть явно включён на VM флагом `--enable-test-adapter`.
- Проверка версии, обязательных полей, типов, статусов и размера JSON-ответа.
- Периодическое обновление, ручной запрос, события клиента и корректная остановка
  собственного SSH-процесса.
- QML-интерфейс с семью вкладками: подключение, климат, датчики/крышка, сеть,
  логи, камера и система.
- При неожиданной потере ранее установленного SSH/API-соединения QML-вариант
  помечает снимок устаревшим и автоматически пытается восстановить туннель.
  Первая повторная попытка выполняется через 5 секунд, последующие интервалы
  увеличиваются до 5, 10, 20 и 30 секунд (максимум — 30 секунд). После
  восстановления запрашивается новый диагностический снимок. Ручное отключение
  и переключение профиля отменяют ожидающие повторы; физические команды не
  отправляются и не повторяются.

## Ограничения этой версии

- Отображается диагностика Linux VM/хоста, а не телеметрия физической станции.
- Нет подключения к ESP32, датчикам, приводам, зарядке, крышке, камере или БАС.
- Нет физических команд, пользовательских ролей, Station ID, сервера, Wi-Fi- и
  проводного каналов. Их нельзя считать реализованными по наличию этого клиента.
- `dockstation-operator` сохраняет прежний Tkinter entry point; текущий
  семивкладочный QML-прототип запускается отдельно командой
  `dockstation-operator-qml`. Основное визуальное направление QML согласовано,
  но продуктовые экраны и сценарии ещё не завершены.
- Последние изменения списка профилей и автоматического восстановления требуют
  повторной ручной проверки на Windows. Host-тесты и Linux offscreen QML-проверки
  не заменяют реальный SSH-сеанс из Windows Operator и испытание остановки/
  повторного запуска Gateway в Ubuntu VM.
- Продуктовая авторизация, серверный каталог OwnerSpace/Station ID и персональные
  псевдонимы, синхронизируемые между устройствами, ещё не реализованы.
- Фактическая повторная проверка текущей QML-версии на Windows и целевого
  Repka Pi 5 выполняется отдельно.
