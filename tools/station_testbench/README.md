# DockStation — настольный испытательный стенд StationStateManager

Первая рабочая версия графического стенда для проверки согласованного вертикального среза ядра.

## Что делает стенд

Графическая оболочка написана на Python 3 / Tkinter. Проверяемая логика остаётся на C++17: при запуске стенд компилирует актуальные файлы из `src/core` текущего репозитория и вызывает функции ядра через отдельный процесс.

В текущей версии реально вызываются:

- F01 `validate_event()` — проверка конверта события;
- F02 `classify_event()` — определение категории события;
- F03 `check_duplicate_event()` — обнаружение повторов;
- F04 `check_event_freshness()` — проверка порядка событий;
- F05 `resolve_transition()` — разрешение/отклонение перехода;
- F10 `commit_transition()` — повторная проверка и фиксация разрешённого перехода;
- F16 `get_snapshot()` — чтение текущего снимка;
- F17 `get_transition_history()` — чтение и проверка истории.

Текущий согласованный сценарий запуска:

1. `POWERED_OFF → STARTUP` по `STARTUP_REQUESTED`.
2. `STARTUP → SELF_TEST` по `INITIALIZATION_COMPLETED`, только если конфигурация подтверждена.
3. `SELF_TEST → WAITING` по `SELF_TEST_COMPLETED`, только если отчёт полный, критические проверки пройдены, безопасное исходное состояние подтверждено и `RecoveryStatus::NotRequired` установлен явно.

Кнопки проверок отказов намеренно показывают, что переход не происходит при нарушении любого из этих условий.

## Что пока не входит в эту версию

- F06–F09, F11–F15 не подключены к графическому сценарию;
- F13 `handle_event()` пока не используется как общий оркестратор;
- известный интерфейсный блокер F13 → F10 с атомарным продвижением SourceCursor остаётся открытым;
- переходы после `WAITING` не реализованы: полная матрица глобальных переходов ещё не утверждена;
- хранилище и публикация `StateChanged` имитируются в оперативной памяти;
- это не сборка под ESP32, не управление приводами и не аппаратный тест.

Стенд полезен для проверки логики первого вертикального среза и поведения при отказах, но его успешный результат нельзя считать интеграционным испытанием всех F01–F17.

## Установка и запуск на Windows

Папку `station_testbench` нужно разместить внутри рабочего репозитория по пути:

`dockstation\tools\station_testbench\`

Тогда структура должна выглядеть так:

```text
dockstation/
  src/
    core/
  tools/
    station_testbench/
      START_TESTBENCH.bat
      testbench_engine.cpp
      testbench_ui.py
```

Требуются:

1. Python 3 для Windows с включённым Tcl/Tk (обычно есть в установщике с python.org).
2. GCC C++17 (`g++`). Рекомендуемый вариант — MSYS2 UCRT64. Установи MSYS2 с официального сайта, открой терминал **MSYS2 UCRT64** и выполни:

   ```bash
   pacman -S mingw-w64-ucrt-x86_64-gcc
   ```

   Затем добавь `C:\msys64\ucrt64\bin` в системную переменную `PATH` (если MSYS2 установлен в стандартную папку). Официальная инструкция: https://www.msys2.org и https://www.mingw-w64.org/getting-started/msys2/.

После этого достаточно дважды щёлкнуть `START_TESTBENCH.bat`. Он сам соберёт движок из текущих исходников `src/core`, затем откроет окно.

Внешние Python-библиотеки не нужны.

## Как проверять

Сначала нажми три штатные кнопки по порядку. На каждом шаге смотри:

- текущее состояние и `revision`;
- журнал прохождения F01–F05 и F10;
- подтверждённую историю переходов F17.

Затем нажми кнопки проверок отказов. Они должны оставлять состояние и revision без изменений, когда соответствующее условие не выполнено.

Кнопка сброса очищает тестовое хранилище и возвращает стенд в `POWERED_OFF`.

## Важное ограничение

Все операции выполняются только внутри тестового процесса на ПК. Стенд не открывает крышку, не подаёт питание на моторы или реле, не управляет катушками зарядки, не обращается к датчикам и не подключается к ESP32. При закрытии окна состояние тестовой симуляции сбрасывается.
