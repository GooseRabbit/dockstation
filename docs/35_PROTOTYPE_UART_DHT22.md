# Прототипная передача DHT22 по UART

## Назначение и границы

Это временный незашифрованный канал только для проверки сквозной телеметрии
двух DHT22: ESP32 → UART → Linux Gateway → локальный API → Windows Operator.
Он не является штатным ControllerLink, не поддерживает команды и не должен
использоваться вне изолированного стенда. Штатный ControllerLink/TLS остаётся
отдельным и не изменяется.

## Профиль соединения

| Параметр | Значение |
|---|---|
| ESP32 UART | UART2 |
| ESP32 TX | GPIO17 |
| ESP32 RX | GPIO16 |
| Скорость | 115200 бод |
| Формат | 8 data bits, no parity, 1 stop bit (8N1) |
| Управление потоком | выключено |
| Период пакета | около 2 секунд |
| DHT22 №1 DATA | GPIO25 |
| DHT22 №2 DATA | GPIO26 |

Для текущего одностороннего потока телеметрии достаточно двух соединений:
ESP32 GPIO17/TX → RX Linux UART и GND ↔ GND. GPIO16/RX задан в профиле UART2,
но Linux пока не отправляет команды, поэтому линию TX Linux → GPIO16 можно
не подключать. Уровни UART — 3,3 В. Не подключать сигналы UART непосредственно
к RS-232 или 5-вольтовому интерфейсу. USB-разъём платы ESP32 остаётся для
питания, прошивки и консоли UART0; сам по себе он не является соединением
UART2 с Linux.

## Формат кадра

Одна ASCII-строка, завершающаяся LF:

**DS1,sequence,esp_uptime_ms,t1,h1,t2,h2**

Числа температуры передаются в °C, влажности — в процентах, с одним знаком
после запятой. **NA** означает, что для соответствующего поля нет свежего
валидного измерения. Linux принимает только семь полей, положительный номер
последовательности, конечные числа и диапазоны DHT22 (−40…80 °C, 0…100 %).
Приёмный буфер ограничен; повреждённые и слишком длинные строки отбрасываются.
Номер последовательности может начинаться заново после перезапуска ESP32.

Пример:

**DS1,12,24000,22.8,41.5,23.1,40.7**

## Настройка Gateway

В используемый Gateway .conf добавляется одна настройка:

**prototype_uart_device=/dev/ttyS1**

Путь выше — только пример. Указать фактически подключённое Linux-устройство
(например, /dev/ttyS1 или /dev/ttyUSB0). Gateway настраивает порт на 115200 8N1,
повторяет открытие при временном отсутствии устройства и отдаёт последний
снимок в поле controller_telemetry существующего /api/v1/system/diagnostics.
Для этого режима параметр штатного controller_uart_device должен оставаться
пустым: два транспорта не могут одновременно владеть одним последовательным
портом.

Стандартный dockstation-gateway.service использует PrivateDevices=true и не
видит физические UART-устройства. Для стендового подключения используется
уже поставляемый systemd-шаблон, который ограничивает доступ одним выбранным
узлом и добавляет группу dialout. Например, для /dev/ttyS1:
- добавить prototype_uart_device=/dev/ttyS1 в /etc/dockstation/gateway.conf;
- выполнить systemctl disable --now dockstation-gateway.service;
- выполнить systemctl enable --now dockstation-gateway-uart@ttyS1.service.

Имя после @ должно совпадать с именем устройства после /dev/. Для USB-UART,
например, использовать ttyUSB0. Не включать одновременно оба сервиса: оба
занимают локальный API-порт 8080.

Данные считаются актуальными в течение 6 секунд после последнего полного
кадра. После этого API сохраняет последнее значение, но устанавливает
link_connected=false и качество измерений STALE. При отсутствии кадра
первый снимок не создаётся.

## Прототипное ограничение

Канал передаёт данные открытым текстом без аутентификации, шифрования,
защиты от подмены и криптографической проверки целостности. Не подключать его
к общедоступным или недоверенным линиям. Перед эксплуатацией заменить его
штатным ControllerLink и пройти отдельную аппаратную приёмку UART/платы.
