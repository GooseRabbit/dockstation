# Прототипная передача телеметрии DHT11/DHT22 по USB/UART

## Назначение и границы

Это временный незашифрованный канал только для сквозной передачи показаний
DHT11/DHT22: ESP32 → USB/UART → Linux Gateway (на обычном ПК или Repka) → локальный
API → Windows Operator. Он предназначен для изолированного прототипного стенда,
не поддерживает команды и не заменяет штатный защищённый ControllerLink/TLS.

Основной физический путь — обычный USB-кабель от разъёма ESP32 к Linux-хосту.
Передавать USB-устройство в виртуальную Windows не нужно: Gateway читает
последовательный порт в Linux, а Operator получает данные через уже существующий
сетевой/API-канал.

## Профиль соединения

| Параметр | Основной USB-путь | Дополнительный UART-путь |
|---|---|---|
| ESP32 интерфейс | UART0 через onboard USB-UART bridge | UART2 |
| Скорость | 115200 бод | 115200 бод |
| Формат | ESP-IDF console log, внутри строка DS1 | 8N1, raw DS1 |
| ESP32 TX | GPIO1 / TX0 через USB bridge | GPIO17 / TX2 |
| ESP32 RX | GPIO3 / RX0 через USB bridge | GPIO16 / RX2 |
| Направление телеметрии | ESP32 → USB → Linux | ESP32 → GPIO17 → RX Linux |
| Период кадра | около 2 секунд | около 2 секунд |
| DHT11/DHT22 №1 DATA | GPIO25 | GPIO25 |
| DHT11/DHT22 №2 DATA | GPIO26 | GPIO26 |

UART0 остаётся штатным USB serial/console/programming interface платы. Прошивка
выводит прототипный кадр через ESP-IDF logger как отдельную строку вида:

`I (1234) DockStationESP32: DS1,12,24000,22.8,41.5,NA,NA`

Linux Gateway извлекает `DS1,...` после стандартного префикса ESP-IDF. Прочие
сообщения загрузчика и системные логи игнорируются. На этом же USB-порту можно
просматривать диагностические строки обычным serial monitor, но Gateway должен
быть единственным процессом, который открывает устройство во время штатной
передачи телеметрии.

UART2 сохраняет отдельный raw-путь для прямого подключения проводами:
ESP32 GPIO17/TX → RX Linux UART и GND ↔ GND. GPIO16/RX задан в профиле UART2,
но для текущего одностороннего потока его подключать не требуется. Уровни UART —
3,3 В. Не подключать сигналы UART непосредственно к RS-232 или 5-вольтовому
интерфейсу. Не настраивать одновременно два Gateway-сервиса на один и тот же
последовательный порт.

## Формат кадра

Одна ASCII-строка, завершающаяся LF:

**DS1,sequence,esp_uptime_ms,t1,h1,t2,h2**

Числа температуры передаются в °C, влажности — в процентах, с одним знаком
после запятой. **NA** означает, что для соответствующего поля нет свежего
валидного измерения. Linux принимает только семь полей, положительный номер
последовательности, конечные числа и общие диапазоны Gateway (−40…80 °C, 0…100 %).
Приёмный буфер ограничен; повреждённые и слишком длинные строки отбрасываются.
Номер последовательности может начинаться заново после перезапуска ESP32.

Пример raw-кадра UART2:

**DS1,12,24000,22.8,41.5,23.1,40.7**

## Настройка Gateway

Сначала определить имя USB serial устройства на Linux:

`ls -l /dev/serial/by-id/`

Для имеющейся платы с CP2102 это обычно `/dev/ttyUSB0`; фактический номер
может отличаться. Для другого USB-UART моста устройство может называться
`/dev/ttyACM0`.

В `/etc/dockstation/gateway.conf` указать фактический путь, например:

`prototype_uart_device=/dev/ttyUSB0`

Gateway настраивает порт на 115200 8N1, повторяет открытие при временном
отсутствии устройства и отдаёт последний снимок в поле `controller_telemetry`
существующего `/api/v1/system/diagnostics`. Параметр штатного
`controller_uart_device` должен оставаться пустым: prototype UART и secure
ControllerLink не могут одновременно владеть одним последовательным портом.

Стандартный `dockstation-gateway.service` использует `PrivateDevices=true` и
не видит физические UART-устройства. Для USB serial используется уже
поставляемый systemd-шаблон, который ограничивает доступ выбранным узлом и
добавляет группе службы `dialout`. Например, для `/dev/ttyUSB0`:

- добавить `prototype_uart_device=/dev/ttyUSB0` в
  `/etc/dockstation/gateway.conf`;
- выполнить `sudo systemctl disable --now dockstation-gateway.service`;
- выполнить `sudo systemctl enable --now dockstation-gateway-uart@ttyUSB0.service`.

Для `/dev/ttyACM0` использовать `dockstation-gateway-uart@ttyACM0.service`.
Имя после `@` должно совпадать с именем устройства после `/dev/`. Не включать
одновременно обычный Gateway и UART-шаблон: оба занимают локальный API-порт 8080.

Windows Operator продолжает подключаться к Linux Gateway прежним способом.
USB ESP32 остаётся подключённым к Linux/Repka; USB passthrough в виртуальную
Windows не нужен.

Данные считаются актуальными в течение 6 секунд после последнего полного кадра.
При физическом отключении USB Gateway обнаруживает состояние tty
`POLLHUP`/`POLLERR`/`POLLNVAL` или ошибку чтения, закрывает старый дескриптор
и немедленно помечает сохранённый снимок как `STALE`. Путь устройства
переоткрывается с интервалом 2 секунды; после повторного подключения Gateway
ждёт первый полный кадр `DS1` и только затем восстанавливает
`link_connected=true`. Перезапуск Gateway не требуется. При обычном истечении
6 секунд без валидного кадра API также сохраняет последнее значение, но
устанавливает `link_connected=false` и качество измерений `STALE`.
При отсутствии кадра первый снимок не создаётся.

## Прототипное ограничение и статус проверки

Канал передаёт данные открытым текстом без аутентификации, шифрования, защиты
от подмены и криптографической проверки целостности. Не подключать его к
общедоступным или недоверенным линиям. Перед эксплуатацией заменить его
штатным ControllerLink и пройти отдельную аппаратную приёмку UART/USB.

ПО для передачи кадра через UART0 и его приёма Linux Gateway покрывается
сборкой и host-тестом. Физическое подтверждение именно пути USB/UART0 → Repka
ещё требуется. Ранее физически проверялся отдельный UART2-путь с обычным
Linux-хостом; это не является проверкой Repka.


## Определение модели датчика

Модель задаётся явно в firmware/esp32/main/app_main.cpp:
- kDhtSensor1Type — модель датчика на GPIO25;
- kDhtSensor2Type — модель датчика на GPIO26.

Для установленного трёхконтактного KY-015 используется DHT11. Для AM2302
или другого совместимого DHT22 нужно указать DHT22 для соответствующего
канала. Автоматического определения модели больше нет: библиотека Adafruit
получает тип при создании объекта датчика и формирует подходящий стартовый
импульс сама.

Чтение выполняется библиотекой Adafruit DHT Sensor Library 1.4.7,
собранной как нативный компонент ESP-IDF. Небольшой DHT_ESP32_Compat.h
предоставляет только GPIO, таймер и critical-section API; измерение импульсов
адаптировано на esp_timer_get_time(). Сам Arduino Core не подключается,
initArduino() не вызывается, стандартный NVS не инициализируется. Формат
DS1, UART, Linux Gateway, API и Windows Operator не меняется.

## Диагностика чтения датчика через USB-консоль

Для каждой попытки чтения прошивка выводит один из двух результатов:

- SUCCESS — библиотека вернула показания, а приложение подтвердило
  допустимые диапазоны для выбранной модели;
- READ_FAILED — библиотека вернула NaN или показания не прошли проверку
  диапазона. API DHT.h не позволяет надёжно определить, был ли причиной
  обрыв/отсутствие ответа, ошибка тайминга или checksum.

Сообщение содержит номер канала, GPIO и результат, например:

W (12345) DockStationESP32: DHT sensor=1 gpio=25 read_status=READ_FAILED

Изменение результата выводится немедленно. Повторяющаяся ошибка для того же
канала выводится не чаще одного раза в 10 секунд; успешные повторные чтения
не засоряют журнал. Каналы опрашиваются независимо, с интервалом не менее
двух секунд. Неудачное чтение не заменяет последнее валидное показание;
после пяти секунд без обновления данные считаются устаревшими. Эти строки
идут по UART0/USB как обычные сообщения ESP-IDF и не меняют семипольный
DS1-кадр, который принимает Gateway.


Gateway во время штатной работы владеет USB serial-портом. Чтобы временно
прочитать диагностические строки, остановить службу, подключённую к
`/dev/ttyUSB0`, выполнить чтение и затем запустить службу обратно:

```sh
PORT="/dev/serial/by-id/usb-Silicon_Labs_CP2102_USB_to_UART_Bridge_Controller_0001-if00-port0"
sudo systemctl stop dockstation-gateway-uart@ttyUSB0.service
sudo stty -F "$PORT" 115200 raw -echo
sudo timeout 15s cat "$PORT"
sudo systemctl start dockstation-gateway-uart@ttyUSB0.service
systemctl is-active dockstation-gateway-uart@ttyUSB0.service
```

Команда чтения сама завершится по тайм-ауту через 15 секунд; код завершения
`124` от `timeout` в этом случае ожидаем. Во время чтения можно один раз
нажать EN/RESET на ESP32, чтобы получить загрузочные строки и первые
диагностические сообщения. Не запускайте одновременно Gateway и второй
serial monitor на одном устройстве.
