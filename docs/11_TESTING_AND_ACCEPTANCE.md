# Испытания и приёмка

**Статус:** предварительный план.  
**Редакция:** 0.2.

## 1. Назначение

Документ описывает подход к проверке программных модулей, аппаратных узлов и всей станции.

Работоспособность должна подтверждаться измерениями и воспроизводимыми испытаниями. Успешная компиляция или утверждение ИИ не являются достаточным подтверждением.

## 2. Уровни испытаний

### Уровень 1. Проверка требований и документации

- проверить непротиворечивость требований;
- определить входы и выходы каждого модуля;
- определить критерии приёмки;
- проверить все открытые вопросы;
- убедиться, что опасные сценарии описаны.

### Уровень 2. Модульные программные тесты

Проверять функции отдельно, без оборудования.

Примеры:

- фильтрация метеоданных;
- проверка устаревших измерений;
- разрешения на операции;
- переходы состояний;
- проверка формата сообщений;
- обработка ошибок;
- контрольные суммы;
- очередь файлов.

### Уровень 3. Имитация оборудования

Использовать программные имитаторы:

- датчика ветра;
- температуры;
- осадков;
- положения крышки;
- наличия БАС;
- BMS;
- зарядного преобразователя;
- камеры;
- сервера;
- бортового накопителя.

### Уровень 4. Стендовые испытания отдельных узлов

- привод крышки;
- датчики;
- механизм очистки;
- зарядная система;
- метеостанция;
- сетевые интерфейсы;
- локальный накопитель.

### Уровень 5. Интеграционные испытания

Проверить взаимодействие подсистем на стенде без полёта.

### Уровень 6. Испытания с БАС

Сначала безопасные наземные испытания, затем отдельные контролируемые испытания посадки и вылета на подготовленной площадке.

### Уровень 7. Климатические и ресурсные испытания

Проверка работы в заявленном диапазоне температур, влажности, осадков, пыли и после многократных циклов.

## 4. Испытания механики

### 4.1. Крышка

- проверка полного открытия;
- проверка полного закрытия;
- проверка концевых датчиков;
- проверка тайм-аутов;
- проверка препятствия;
- проверка перегрузки;
- проверка после отключения питания;
- проверка ручного освобождения;
- проверка ресурса циклов.

### 4.2. Самоочистка

- проверка работы без БАС;
- проверка блокировки при наличии БАС;
- проверка различных типов загрязнений;
- проверка отвода загрязнений;
- проверка заклинивания;
- проверка влияния воды, снега и льда;
- проверка ресурса.

## 5. Испытания метеостанции

- сравнение с контрольными приборами;
- проверка скорости и направления ветра;
- проверка порывов;
- проверка температуры и влажности;
- проверка осадков;
- проверка атмосферного давления;
- проверка связи;
- проверка временных меток;
- проверка реакции на отказ;
- проверка влияния корпуса и пропеллерных потоков.

## 6. Испытания посадочной системы

До испытаний определить:

- систему координат;
- требуемую точность;
- геометрию маркера;
- калибровку камеры;
- частоту измерений;
- допустимую задержку;
- протокол автопилота;
- сценарии потери маркера;
- критерии подтверждения посадки.

Последовательность испытаний:

1. Проверка детекции неподвижного маркера.
2. Проверка расчёта координат на известных положениях.
3. Проверка ориентации.
4. Проверка задержки измерений.
5. Проверка качества при разном освещении.
6. Проверка частичного закрытия маркера.
7. Проверка потери изображения.
8. Проверка обмена с автопилотом в симуляции.
9. Наземная проверка без пропеллеров.
10. Контролируемые испытания полёта на безопасной площадке.

Не переходить к полётным испытаниям, пока не проверены координатные преобразования, направление поправок, задержки и отказные сценарии.

## 7. Испытания зарядки

- измерение входной мощности;
- измерение передаваемой мощности;
- расчёт КПД по согласованной методике;
- проверка выравнивания катушек;
- проверка влияния смещения;
- проверка температур;
- проверка посторонних металлических предметов;
- проверка BMS;
- проверка отключения при отказе;
- проверка времени зарядки;
- проверка работы при крайних температурах в допустимых условиях.

КПД необходимо считать по чётко определённым точкам измерения. Нельзя сравнивать КПД преобразователя с КПД всей системы как одно и то же значение.

## 8. Испытания передачи данных

- малый файл;
- большой файл;
- несколько файлов;
- обрыв соединения;
- отключение питания;
- повторная передача;
- повреждённый блок;
- неверная контрольная сумма;
- недоступный сервер;
- переполнение накопителя;
- неверный сертификат;
- неавторизованное устройство;
- восстановление очереди после перезапуска.

## 9. Интеграционные сценарии

### Сценарий A. Штатный цикл

1. БАС возвращается.
2. Станция обнаруживает и идентифицирует его.
3. Проверяет готовность.
4. Открывает крышку.
5. Обеспечивает посадочное сопровождение.
6. Подтверждает посадку.
7. Выполняет обслуживание.
8. Получает материалы.
9. Отправляет материалы.
10. Заряжает аккумулятор.
11. Проверяет наличие следующего заранее разрешённого задания.
12. При отсутствии запретов и выполнении всех условий автоматически готовит следующий вылет без обязательного подтверждения специалиста после каждой миссии.
13. Выполняет вылет.
14. Очищает площадку.

### Сценарий B. Закрытое обслуживание

После посадки и подтверждения безопасного состояния крышка закрывается. Проверяется закрытое положение. Только после этого допускаются предусмотренные процессы зарядки и передачи данных. Отдельно проверяется, что закрытый корпус не нарушает радиосвязь, обмен с BMS и работу зарядной системы.

### Сценарий C. Автоматический следующий цикл

Станция получает заранее разрешённую миссию, выполняет проверки и начинает следующий цикл без обязательного ручного подтверждения каждого результата. Затем повторить испытание с пустой очередью, просроченной миссией, запретом безопасности и удалённой командой остановки — вылет не должен начинаться.

### Сценарий D. Потеря интернета

Проверить, что локальная работа не прекращается, файлы сохраняются, очередь восстанавливается.

### Сценарий E. Отказ метеостанции

Проверить блокировку планового вылета и предусмотренную реакцию на возвращающийся аппарат.

### Сценарий F. Отказ крышки

Проверить остановку привода, запрет несовместимых операций и уведомление.

### Сценарий G. Перегрев зарядки

Проверить независимое отключение силовой части.

### Сценарий H. Потеря визуального сопровождения

Проверить, что недостоверные поправки не продолжают передаваться автопилоту.

### Сценарий I. Перезапуск при незавершённой передаче

Проверить восстановление очереди и целостность файлов.

## 11. Критерии готовности модуля

Модуль можно считать готовым к интеграции, если:

- его назначение и интерфейс описаны;
- код соответствует интерфейсу;
- ошибки обрабатываются;
- есть модульные тесты;
- тесты пройдены;
- нет известных критических дефектов;
- результат проверен на целевом оборудовании, если модуль аппаратный;
- документация обновлена;
- ограничения известны.

Готовность к интеграции не равна готовности к эксплуатации.

## 12. Критерии готовности всей станции

Вся система может считаться прошедшей этап прототипа только при наличии:

- утверждённого набора требований;
- согласованной архитектуры;
- работающих модулей;
- успешных интеграционных тестов;
- проверенных защитных реакций;
- испытаний с выбранным БАС;
- испытаний зарядки;
- испытаний климатических условий;
- протоколов и журнала дефектов;
- эксплуатационной документации.

## 13. Запрет на фиктивную приёмку

ИИ или разработчик не может отметить испытание как пройденное, если тест фактически не запускался.

Нельзя подменять:

- «код написан» на «код проверен»;
- «собирается» на «работает на оборудовании»;
- «работает на стенде» на «готово к эксплуатации»;
- «передача завершена» на «сервер подтвердил целостность».
